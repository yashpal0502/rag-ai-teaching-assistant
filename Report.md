# RAG-Based AI Teaching Assistant

A Retrieval-Augmented Generation (RAG) application that helps learners
find explanations in the Sigma Web Development course. Users ask
course-related questions through a Streamlit chat interface, retrieve
relevant transcript segments, and receive answers generated by an
Ollama-hosted language model with video titles and timestamps.

# Abstract

This project presents a Retrieval-Augmented Generation (RAG)-based AI Teaching Assistant designed to help learners locate explanations within the Sigma Web Development course by CodeWithHarry. The system processes course videos into timestamped transcript chunks, represents the chunks as vector embeddings, retrieves relevant material for a user's question, and passes the retrieved context to a large language model to generate a natural-language response. The application is exposed through a Streamlit chat interface.

The implementation uses Whisper for speech transcription, FFmpeg for audio extraction, BGE-M3 for embeddings, cosine similarity for semantic retrieval, Ollama as the local model runtime, and Llama 3.2 for response generation. Transcript metadata such as video title, video number, and start/end timestamps is retained so that answers can direct learners to the relevant course segment. The current dataset contains 312 transcript chunks, and the embedding vectors have 1024 dimensions. The project focuses on a working local prototype; formal retrieval-quality measurements and cloud deployment are identified as future work.

## Keywords

Retrieval-Augmented Generation, RAG, semantic search, embeddings, BGE-M3, cosine similarity, Whisper, Ollama, Llama 3.2, Streamlit, AI Teaching Assistant.

# 1. Introduction

Recorded educational courses contain substantial information distributed across many videos and long transcripts. A learner who remembers a topic but not the lesson in which it was explained may need to search manually through multiple videos. This can interrupt the learning process and make revision less efficient.

The RAG-Based AI Teaching Assistant addresses this navigation problem by combining semantic retrieval with language generation. A learner submits a natural-language question. The system searches the transcript dataset for semantically relevant segments and provides those segments to a language model as supporting context. The generated response can explain the relevant material and identify the video and timestamp where it appears.

# 2. Problem Statement

Learners often find it difficult to identify the exact video and timestamp at which a concept is taught in a lengthy recorded course. Keyword-based searching may fail when the learner uses different wording from the instructor. A system is therefore needed that can interpret the meaning of a question, retrieve relevant course transcript segments, and present an answer with source-location information.

# 3. Aim and Objectives

The aim is to develop a course-specific AI assistant that answers learner questions using retrieved transcript context and helps learners navigate to the relevant course material.

- Extract audio from course videos for transcription.

- Generate timestamped transcript chunks from course audio.

- Create vector embeddings for transcript chunks using BGE-M3.

- Store transcript text, metadata, and embeddings for reuse.

- Retrieve relevant chunks for a natural-language query using cosine similarity.

- Construct a context-grounded prompt and generate an answer using Llama 3.2.

- Provide a Streamlit chat interface that displays answers and source information.

# 4. Scope of the Project

The current prototype is focused on the Sigma Web Development course and uses the transcript material available in the project dataset. It supports question answering over the indexed transcript chunks and presents associated video metadata and timestamps. It is not designed as a general-purpose assistant or as a replacement for the original course.

The tutorial step that merges every five consecutive transcript chunks into larger chunks has been intentionally excluded at this stage. The current application continues to use the existing chunk dataset and its corresponding embeddings.

# 5. Background and Core Concepts

## 5.1 Retrieval-Augmented Generation

Retrieval-Augmented Generation is an approach in which relevant information is retrieved from an external knowledge source and supplied to a language model when generating an answer. In this project, the external knowledge source is the indexed course transcript dataset. Retrieval provides course-specific context, while the language model converts that context into a readable response.

## 5.2 Speech-to-Text Transcription

Speech-to-text converts spoken audio into text. The project uses FFmpeg to extract audio from video files and Whisper to transcribe the audio. The transcript is organized into chunks with timing and video metadata so that the resulting text remains connected to its source.

## 5.3 Text Embeddings

An embedding is a numerical vector representation of text. Texts with related meanings are intended to have vector representations that are close under an appropriate similarity measure. BGE-M3 is used to generate embeddings for transcript chunks and user queries. The project dataset has 1024-dimensional embeddings.

## 5.4 Semantic Search and Cosine Similarity

Semantic search retrieves content based on meaning rather than requiring exact keyword matches. The system embeds the user's question and compares it with stored chunk embeddings using cosine similarity. The chunks with the highest similarity scores are selected as retrieval results.

## 5.5 Large Language Model

A large language model generates a natural-language answer from the supplied prompt. The project uses Llama 3.2 through the Ollama API. The prompt includes the user's question and the retrieved transcript text with video metadata. The prompt instructs the model to answer course-related questions using the supplied context and to avoid inventing source titles or timestamps.

# 8. Methodology and Implementation

## 8.1 Video-to-Audio Conversion

FFmpeg is used to extract audio from the course videos and save the audio files for transcription. This separates the audio-processing step from the later retrieval and question-answering steps.

## 8.2 Audio Transcription and Chunk Metadata

Whisper is used for speech transcription. In the tutorial workflow, the transcription configuration uses Hindi as the input language and the translate task to produce English text. Transcript segments are stored in JSON with fields including video number, title, start time, end time, and text.

## 8.3 Embedding Generation

The project uses the BGE-M3 model through the Ollama embeddings API. Each transcript chunk's text is passed to the embedding function, which returns a 1024-dimensional vector. The vector is associated with its transcript metadata and a chunk identifier.

The recorded dataset contains 312 chunks. Their text, metadata, and embedding vectors are assembled into a Pandas DataFrame and persisted using Joblib so the application does not need to regenerate all transcript embeddings every time it starts.

## 8.4 Loading and Validating the Embeddings

The retriever loads the saved DataFrame from the configured embeddings path. It checks that the file exists, that the loaded object is a DataFrame, that it is not empty, and that the required metadata and embedding columns are present.

## 8.5 Semantic Retrieval

When a user submits a question, the query is embedded using the same embedding model. The stored vectors are arranged into a matrix and compared with the query vector using cosine similarity. The results are sorted in descending similarity order and the requested top-K rows are returned. A similarity score is retained for each retrieved result.

## 8.6 Prompt Construction

The RAG pipeline selects the retrieved chunks' title, video number, start time, end time, and transcript text. These fields are serialized into JSON-formatted context and inserted into a prompt with the user's question. The embedding vectors themselves are not sent to the language model because the model needs the readable transcript context.

## 8.7 Response Generation

The prompt is sent to the Ollama generate API using the configured Llama 3.2 model and non-streaming response mode. The pipeline handles common connection, timeout, and HTTP errors and returns the generated answer along with the retrieved source rows.

## 8.8 Streamlit Application

The Streamlit application provides a chat input, message history, a sidebar control for the number of chunks to retrieve, and expandable source details. The embeddings DataFrame is cached as a resource so it can be reused across Streamlit reruns in the application session. Chat messages are maintained using Streamlit session state.

# 9. User Interface and Application Workflow

1. The user opens the Streamlit application.

1. The application loads the precomputed embeddings DataFrame.

1. The user enters a question related to the course.

1. The user may adjust the number of chunks to retrieve.

1. The RAG pipeline retrieves relevant transcript chunks and generates an answer.

1. The interface displays the answer and an expandable section containing source video information and timestamps.

# 11. Limitations

- The current knowledge base is limited to the available Sigma Web Development course transcripts.

- Retrieval quality depends on transcription quality, chunk boundaries, embedding quality, and the selected top-K value.

- The current prototype uses a local Ollama endpoint. A deployed cloud application cannot access the developer's personal localhost service.

- The proposed merging of five consecutive transcript chunks has been excluded; the existing chunk dataset and embeddings remain in use.

- The report does not claim measured accuracy, response latency, or a formal benchmark because these results have not been supplied.

- The current chat history is maintained in Streamlit session state and is not described as permanent database storage.

# 12. Future Enhancements

- Evaluate retrieval quality using a curated set of questions and expected source segments.

- Compare chunk sizes and overlap strategies before changing the existing dataset.

- Explore contextual compression or reranking to reduce irrelevant retrieved context.

- Add direct video links or playback controls that open the relevant timestamp.

- Add a relevance threshold and a clear fallback when no useful transcript context is found.

- Provide a cloud-compatible inference endpoint and secure deployment configuration.

- Improve observability with request logging, error reporting, and response-time measurement.

# 13. Conclusion

The RAG-Based AI Teaching Assistant demonstrates how semantic retrieval and language generation can be combined to make recorded course material easier to search. Course videos are processed into timestamped transcript chunks, represented as BGE-M3 embeddings, and stored for reuse. For a learner's question, the system retrieves relevant chunks using cosine similarity and supplies their text and metadata to Llama 3.2 through Ollama. A Streamlit interface presents the generated response and the associated video references.

The current implementation establishes the main local RAG workflow. Further evaluation, retrieval improvements, and cloud-compatible model serving are required before the system can be considered production-ready.
